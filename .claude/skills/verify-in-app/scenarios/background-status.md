## Mobile background status

Run `flutter test --concurrency=1 test/background/background_check_status_test.dart test/background/background_check_controller_test.dart test/background/background_check_section_test.dart test/background/background_check_dialog_test.dart test/background/background_refresh_test.dart test/notification_settings_test.dart`. In an isolated mobile client, inspect first use, permission denial, unavailable capability, interrupted and partial checks, account switching, and resume. Verify that a fresh permission result replaces an old denial warning while the dialog is open. Scheduling registration and OS posting acceptance do not prove delivery; these states must remain separate. Never change a denied OS permission or create a fresh identity to obtain a new permission decision without the user's explicit authorization.
