# Architecture guards and the baseline ratchet

`test/architecture/` scans source files and fails CI when a new call site breaks a repo rule. Known old violations are listed in `test/architecture/baseline/<ns>.yaml`; the list can only shrink.

## The ratchet

- One baseline file per namespace: `test/architecture/baseline/<ns>.yaml` (`arch`, `style`, `test`), mapping rule id (`<ns>.<name>`) to (repo-relative path to allowed count). A rule with no violations has no entry. Each namespace has exactly one test file that calls `ratchetTests(rules, namespace: '<ns>')` directly in the body of its top-level `main()` (a helper, a closure, a tear-off or a non-literal namespace fails); `ratchet_test.dart` fails when a namespace is registered from two files or a baseline file has none.
- A count above its entry, or a file not listed, fails with the offending lines and the building block to use instead.
- A count below its entry fails too, with the edit to make: `lower <rule> <path> to N`, or remove the entry (and the rule id line if it was the last; an empty `arch.x:` still parses). That is how the debt only goes down.
- A baseline id that none of the namespace's rules claims fails, and a rule id registered twice throws.
- `UPDATE_BASELINE=1 flutter test test/architecture` makes the edits for you. It never raises a count or adds an entry, and it removes entries and rule ids left with no entries. It keeps ids no rule claims (and the orphan test still fails): once a rule is really gone and its id removed from the code, run `UPDATE_BASELINE=prune flutter test test/architecture` once to drop them. Each file has one writer, so no lock is needed; the write goes through a temp file and a rename.

## When a guard fails

1. Read the message: it names the building block to use. Use it.
2. If the new site is legitimate (the block itself, a platform boundary), add its path to the rule's allowlist in code with a reason, and say why in the PR. Never raise or add a baseline entry.
3. If the count fell, run the update command above (or make the edit the message gives) and commit the baseline file.

## Adding a rule

1. Write the scan. A `Rule` (`ratchet.dart`) has `id`, `scan` (path to violation count), `locate` (offending lines of one path, for the failure) and `message` (what to use instead; name the shared building block, a rule without one is not finished).
2. Register it with `ratchetTests([...], namespace: 'arch')` in a test file under `test/architecture/`. The `arch.*` rules are the table `guardRules` in `architecture_guards_test.dart`; `source_scan.dart` gives a comment-free view of each file (`SourceFile.text` keeps string literals, `SourceFile.code` blanks them, so a call pattern never matches text in a string).
3. Run the scan on main and read every hit. Allowlist the legitimate paths in code, with a reason. Baseline only real violations you will not fix in this change: `UPDATE_BASELINE=1` never adds, so write those entries by hand with the counts the failure reports.
4. Prove the rule can fail: add one violating line to a `lib/` file, run `flutter test test/architecture`, see the failure with the right message, revert it. Do not commit the line. A rule over `test/` (`arch.tests-read-docs`) needs a temporary file under `test/` instead, deleted afterwards.
5. Keep the whole directory fast (it may run in a pre-commit hook): read files once, no process spawns.

## Test rules

- `test.geometry-focus-by-tab` (`test_conventions_test.dart`): a test file that checks a focus ring's shape (`expectRingHugs`, `expectInsideClip` or `expectInsideRow`) must reach focus with `tabTo(tester, finder)` (`test/support/tab_to.dart`: Tab until the primary focus is inside the finder, a bounded loop that fails with where the focus is), not with `requestFocus`, `_focus` or `_focusInk`. A node focused by hand can be one no Tab reaches, which is how the Mac `GroupedMenuRow` showed no ring while its case passed. The scan counts every call of `_focus(`, `_focusInk(` and `.requestFocus(` in such a file; only the helpers' own definitions (`_focusByRequestHelpers`: `_focus`, and `_focusInk`, which focuses a row's own ink well so that a button inside the row is not the focused control) are skipped, so a new call of either helper moves the ratchet. The baseline (`test/focus_ring_geometry_test.dart`: 34 = 30 `_focus` + 2 `_focusInk` + 2 `requestFocus`) only goes down. The self-test group in the same file shows a `requestFocus` case and a `_focusInk` call failing and a `tabTo` case passing.

## Known gaps

The scans read text, not types, so some slips get through. They are known, and a review is still the backstop:

- `arch.error-interpolation-in-telemetry`: an error handler held in a variable (`final handler = (e, st) {...}; fut.catchError(handler)`), a helper that takes the error as a parameter with another name and logs it, an error built into a string before the call (`final msg = '$e'; debugPrint(msg)`), and the errors of an isolate (`ReceivePort.listen` on an `addErrorListener` port).
- `arch.doctor-fix`: a route held in a `const` and passed by name, and a string split across two literals (`'--fi' 'x'`, `'/api/ops/' 'doctor'`).
- `test.localization-delegates` scans only for the text `AppLocalizations.localizationsDelegates`. A hand-built delegate list (`[AppLocalizations.delegate, GlobalMaterialLocalizations.delegate, ...]`) or a bare `GlobalMaterialLocalizations.delegates` has no `material_ui` bridge and the scan cannot see it: review any new test `MaterialApp` for `kTestLocalizationsDelegates`.
- `arch.inkwell-without-focus-ring` reads the analyzer's unresolved syntax tree (what encloses the call), not types. It reads every handler that makes an ink well focusable (`onTap`, `onDoubleTap`, `onLongPress`, `onLongPressUp`, `onTapUp`, `onTapDown`, `onSecondaryTap`, `onSecondaryTapUp`, `onSecondaryTapDown`) and accepts a ring owner only in its `child:` slot, stopping at the first enclosing ink well and at any function body. It misses an ink well built by a helper whose result is wrapped in a ring elsewhere (that site is a hit and goes on the allowlist as `path#Class`, as `GroupedRowInk` does), a `GestureDetector` (read by `arch.gesture-detector-without-focus`, next) and any other tap widget that is not an `InkWell` or `InkResponse`.
- `arch.gesture-detector-without-focus` (sibling of the ink-well guard, same syntax-tree approach and walk: it stops at any function body, any declaration and the first enclosing detector) flags a `GestureDetector(` with a non-null tap-like handler: `onTap`, `onTapUp`, `onTapDown`, `onDoubleTap`, `onLongPress`, `onLongPressStart`, `onLongPressUp`, `onSecondaryTap`, `onSecondaryTapUp`, `onSecondaryTapDown`. Not read: drag, scale, pan, force-press, `onTapCancel`, `onDoubleTapDown`, `onLongPressEnd` (a detector with only those is no tap target). The only owner is `FocusableTap`, in whose `child:` slot the detector is built, or reached from the detector through its own `child:` chain (Padding, Semantics and the like). `Focus` is not one (a tab stop with no Enter or Space; `canRequestFocus: false` takes none), a bare `FocusableActionDetector` is not (it needs actions and `enabled`, which `FocusableTap` carries), and `FocusRing` alone is not (it draws, it does not focus). The allowlist `_gestureDetectorKeyboardElsewhere` is `path#Class` and takes only the reasons "over a focusable control: ..." (a pointer-only extra path, such as a long press, right-click or double tap, over a control the keyboard reaches with the same action or an equivalent) or "beside a focusable control: ..." (a focusable control next to it does the same); a test checks the prefix, and no "until X" entry is accepted. Known gaps, none read: a `GestureDetector` built by a helper (the helper's own call site is what is read, and a detector in a local that is later wrapped in an owner is a hit, so it goes on the allowlist, as `_AttachmentThumbnailState` does); a `Listener` or a `RawGestureDetector` (`quick_look_target.dart`, `screen_gesture_layer.dart`); and a missing keyboard path to a row's actions (F.474): the guard checks that the tap target itself is reachable, but a detector whose action has no keyboard path at all is a baseline entry, not an allowlist one: the hold-to-record send control (F.463), the thread row's long press and `TouchRowMenu` (F.474) and `RowActions` (new roadmap row). Where a Mac menu-bar command or a focusable control does the same, it is allowlisted with that named (`_MacSourceListTileState`, `InspectorLayout`).
- A bare `e`, `ex` or `st` is only an error name where a catch, a `catchError`/`handleError`/`onError`/`runZonedGuarded` handler or a `StackTrace`/`FlutterErrorDetails` parameter binds it.
- `arch.english-default-label` reads the analyzer's unresolved syntax tree for a plain string literal default on a named or optional positional parameter (`String x = 'Ok'`, `this.x = '...'`, `super.x = '...'`) and calls it English when it starts with a capital letter, holds a space or ends in `. ! ? : ...`. It misses a default built from a constant (`= kCancel`, a `static const` English string), a literal with interpolation, an all-lowercase word (`'search'`), a label that is a field initialiser or a local, and an English literal passed at a call site (`label: 'Install'`) rather than defaulted. A default that is not visible text (a file name handed to another app) goes on `_englishDefaultNotVisibleText` as `path#parameter`.
- `arch.english-null-fallback` flags `?? '<text with a letter>'` (single or double quotes, also across a line break, and a literal inside a `${...}` interpolation, as in `tool_value_view.dart`) in a file under `lib/src/` that imports the widget layer, and in the `part of` files of such a library (the parent named by `part of '...';` is read for its imports). It is the expression form of the English fallback that `arch.english-default-label` and `style.string` do not see. It reads text, not types: it also hits a literal that is not visible text (a font family, 'macOS', the 'Hermes' brand, a profile id). Those go on `_englishNullFallbackNotVisibleText` as `path` with an exact count and a reason; a file above its count reports all its hits, so a file with real labels beside one such hit must have them translated first (`hermes_code_block.dart` did). It misses a fallback held in a constant (`?? _fallback`), a literal with no letter, a `.isEmpty ? 'x' : y` ternary, a `part of 'x'` whose parent is named by library name (none exist). Its first hits were translated or allowlisted, so `baseline/arch.yaml` holds none. Translated count messages are guarded apart, by `test/l10n/count_plural_test.dart` (a message with an int or num placeholder needs a plural, or an entry on `_noPlural` with a reason; ask of each entry whether a verb or noun elsewhere in the sentence agrees with one of the numbers).
- `arch.english-default-label` also hits values that look like words but are not visible text: capitalised ids, header names and date patterns (`'StateError'`, `'Content-Type'`, `'HH:mm'`, `'MMM d, yyyy'`, `'Bearer '`). Such a default goes on `_englishDefaultNotVisibleText` as `path#parameter` with a reason. It misses a default that is a `const` or `static const` holding English (`failure = _fallback` in `plugin_actions.dart:16`).
- `arch.label-helper-takes-l10n` reads the analyzer's unresolved syntax tree of every file under `lib/` (a file that does not import the widget layer too, as `mcp_presentation.dart`) for a top-level function or getter, or a method or getter (static or not) of a class, enum, mixin, extension or extension type, named `*Label`, `*Title` or `*Summary` (or exactly `label`, `title`, `summary`), that returns `String`, `String?`, `Future<String>`, `Future<String?>`, `FutureOr<String>`, `FutureOr<String?>`, `Stream<String>`, `Stream<String?>` or has no declared return type (an `async` body and its `return` statements are read like any other, and an `async*` body's `yield` statements too), takes no parameter typed `AppLocalizations` or `BuildContext`, and returns a string literal that holds a Latin letter (`×` and `÷` are not letters). A literal counts in a returned expression, also inside the `${...}` of an interpolation (`'${done ? 'Done' : 'Open'}'`), outside call arguments, index expressions, function literals, `==` and `!=` operands, `throw` expressions and switch-expression patterns (the arm's value counts, `'a' => 'Done'` hits on `'Done'`). Pass `AppLocalizations` instead, as `kanbanStatusLabel(l10n, status)` and `effortLabel(l10n, effort)` do. A helper whose text nobody reads (an id, a semantic identifier, a debug label, a server value passed through) goes on `_labelHelperNotVisibleText` as `path#name` (`path#Type.name` for a static method) with its reason. It misses a `Stream` helper that builds its text in a call (`Stream.value('Done')`), a helper under another name (`*Name`, `*Text`, `*Description`), a literal held in a constant or a variable, and a literal inside the arguments of a returned call (`Text('Done')`, `s.replaceAll('a', 'b')`). Its first hits were translated. The scan of instance methods, getters and files outside the widget layer found 10 more: `memoryEntryLabel` was translated, `ProvidersScreen._profileLabel` (the profile id `default`) is on `_labelHelperNotVisibleText`, and 8 sit in `baseline/arch.yaml` (set by hand with the counts the failure reported, as step 3 of adding a rule says: `bot_handoff_body.dart`, `tool_call_presentation.dart`, `mcp_presentation.dart` 3, `platform_hint_prompt.dart`, `schedule_models.dart`, `call_readiness.dart`).
