# Auth

**Auth.** Both OIDC and password sign-in use the same RFC 8252 flow (`auth/native_login_flow.dart`, `pkce.dart`): a browser, loopback HTTP listener, PKCE, then a bearer token pair kept in secure storage (`auth/token_store.dart`; on iOS readable after the first unlock, so a watch request can wake the locked phone app and still find the session). The browser (`auth/sign_in_browser.dart`) is an `ASWebAuthenticationSession` sheet on iOS and macOS (`WebAuthSession.swift` in each runner, channel `hermes_app/web_auth`), which App Review requires, and the external browser elsewhere. When AuthenticationServices refuses to start a sheet (it can keep refusing until relaunch), the Runner tries once more after 0.5 s and `FallbackSignInBrowser` then opens the external browser, whose callback gets the done page instead of the redirect. Hermes only accepts a loopback `redirect_uri`, so on Apple platforms the listener answers the callback with a redirect to `hermes-app-signin://` to end the sheet. Token-store reads never rewrite or delete their snapshot. All native secure-store mutations use a SQLite connection lock (`auth/session_mutex_native.dart`, `sqlite3`); its database contains no credentials. Refresh writes and automatic expiry deletes compare the expected pair under that lock, so other engines cannot overwrite a newer session or undo sign-out. A foreground refresh whose storage write fails is retried while idle and before another request without refreshing again; background persistence retries are bounded by shutdown grace. A stored session is only sent to the dashboard that minted it (`HermesSession.serverUrl`, checked by `sessionServes`); one stored before the minter was recorded is taken as the saved (or dev override) address's and never goes to an address the user types. Before `connect` replaces the saved address, `TokenStore.recordMinter` binds such a session to the old address (or the address a same-host redirect of it led to) under the session lock; if that fails the saved address stays, and with no saved address to bind to the session is removed. So the headless runtime, which trusts the saved address, never meets an unbound session that belongs elsewhere. Tokens refresh before use and again on any 401. A refresh answered with 400 or 401 ends the session; a 403 does so only with Hermes' own `{"error": "session_expired"}` body (`NativeLoginException.rejected`), since Hermes never sends 403 there and a proxy's 403 must not sign the user out. Concurrent 401s must not sign the user out, and sign-in must never be left spinning (regressions fixed in 0.1.8 and 0.1.9). A request answered 401 costs at most one refresh and one more try (`hermes_retried`; a second 401 on the current token ends the session), so a caller that asks again meets a signed-out client, not another refresh. The authenticated client (not the connect probe) sends a GET again when it got no answer because the connection failed (`connectionError`, `connectionTimeout`), at most twice, with a random wait below a bound that doubles from 0.5 s (`api/get_retry_interceptor.dart`, behind the telemetry interceptor so every try keeps its span); a POST, PUT, PATCH or DELETE, a receive timeout and an error status are never sent again there. If `/api/status` reports `auth_required: false`, sign-in is skipped. Cleartext is local-only by app logic (`auth/server_address.dart`, `isLocalHost`: loopback, RFC 1918, link-local, CGNAT/tailnet, IPv6 ULA, `.local`/`.lan`/`.home.arpa`/`.internal`/`.ts.net`, single-label names): `normalizeServerUrl` gives a schemeless public host `https://`, the setup screen asks (`confirmCleartextServer`) before an `http://` public address and `connect` refuses one without `allowCleartext` (saved addresses are exempt), and a probe redirect to cleartext public is refused. A saved public `http://` address that was saved before the app asked, or that the user never accepted, is asked about once (`AuthController.unconfirmedCleartextServer`, set by `bootstrap`; `SavedCleartextGate` shows `confirmSavedCleartextServer` only while the connection is ready or waits for the sign-in, never while connecting or signing in): Keep http:// (`keepCleartextServer`) adds the address to the accepted list (`kAcceptedCleartextServersKey`, shared preferences, per address, no secret; `connect` with `allowCleartext` adds it too), Use https:// (`useHttpsForCleartextServer`) probes the https form first and only then connects to it (the session the http:// address issued is not served there, so a gated server asks for the sign-in again); a snackbar says it is checking, and when https does not answer (or sends the app back to http://), the saved connection stays, a snackbar says so and the question comes back next launch; a question that went stale meanwhile (`HttpsSwitch.superseded`) does nothing. A question closed without a choice (outside tap, back button, the connection ending) is no answer: the gate does not ask again until the connection is lost. `connect` records an acceptance only after the address answered, and a failed preferences write never fails it. The saved connection works meanwhile, and `withHeadlessHermes` never asks and never records an acceptance. Local hosts and the dev override are never asked about. Android keeps `usesCleartextTraffic` because its network security config cannot express private ranges. A failed connect is classified in `auth/connect_failure.dart`; the setup screen adds a VPN hint for tailnet/private addresses, and `network/network_signals.dart` (`connectivity_plus` plus app resume) makes `AuthController` retry the saved server after a network failure. On Linux the plugin talks to NetworkManager over the system D-Bus: `Connectivity()` is created only when a system bus exists (`DBUS_SYSTEM_BUS_ADDRESS` or a `system_bus_socket` under `/var/run/dbus` or `/run/dbus`; containers and headless setups have none), and then its listen and check run in an error zone, since the plugin rethrows from inside the stream's `onListen` where no `onError` reaches; that zone swallows only bus errors (`SocketException`, the `dbus` package's `DBus...`-named exceptions such as a missing NetworkManager, and any `String` (only that package throws raw Strings there) or a `FormatException` naming a "D-Bus address" (its address parser), while any other `FormatException` goes to the parent zone; `DBUS_SYSTEM_BUS_ADDRESS` is read as one address, as the package does, and counts as a bus only when it is `unix:` with `path=` or `abstract=`, or `tcp:` with `host=`, a numeric `port=` and an ipv4 or ipv6 `family=` if given, so a malformed one never starts the plugin), every other error goes to the parent zone and the crash reporter. A missing bus or NetworkManager degrades to the app-resume nudge with no uncaught error. The app reads a VPN only on Android and Windows (`_reportsVpn`), though the plugin reports one on Linux too. VPN detection is only a hint, never a gate: iOS and macOS cannot report it. An untrusted certificate (Caddy's `tls internal`) is its own failure kind with a hint on trusting the root; on Android, where Dart reads only the system store, `network/user_certificates.dart` adds the user-installed CA certificates to the default `SecurityContext` at launch, in `prepareBackgroundIsolate` and on resume. `--dart-define=HERMES_SERVER_URL=<url>` overrides the saved server address, for dev and tests. When the connection ends (state leaves `ready`, or `ownerGeneration` moves while it is `ready`), `ConnectionPageCloser` removes every page, dialog, sheet and menu above the home route before the login or setup screen builds (see app-shell.md); a refresh, even one that has to retry, changes neither signal. An ungated server's sign-out is the path where the generation moves while the state stays `ready`: `_RootRouter` then builds a new `AppShell` for the new owner once protected requests are allowed again (app-shell.md). When the saved server address cannot be read (`readSaved`, reported through `reportUnreadablePrefs`), `bootstrap` ends on `needsServerUrl` instead of staying on initializing, and leaves the stored session alone; an unreadable accepted-http list counts as "not accepted".
