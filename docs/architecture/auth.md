# Auth

**Auth.** Both OIDC and password sign-in use the same RFC 8252 flow (`auth/native_login_flow.dart`, `pkce.dart`): a browser, loopback HTTP listener, PKCE, then a bearer token pair kept in secure storage (`auth/token_store.dart`; on iOS readable after the first unlock, so a watch request can wake the locked phone app and still find the session). The browser (`auth/sign_in_browser.dart`) is an `ASWebAuthenticationSession` sheet on iOS and macOS (`WebAuthSession.swift` in each runner, channel `hermes_app/web_auth`), which App Review requires, and the external browser elsewhere. When AuthenticationServices refuses to start a sheet (it can keep refusing until relaunch), the Runner tries once more after 0.5 s and `FallbackSignInBrowser` then opens the external browser, whose callback gets the done page instead of the redirect. Hermes only accepts a loopback `redirect_uri`, so on Apple platforms the listener answers the callback with a redirect to `hermes-app-signin://` to end the sheet. Token-store reads never rewrite or delete their snapshot. All native secure-store mutations use a SQLite connection lock (`auth/session_mutex_native.dart`, `sqlite3`); its database contains no credentials. Refresh writes and automatic expiry deletes compare the expected pair under that lock, so other engines cannot overwrite a newer session or undo sign-out. A foreground refresh whose storage write fails is retried while idle and before another request without refreshing again; background persistence retries are bounded by shutdown grace. A stored session is only sent to the dashboard that minted it (`HermesSession.serverUrl`, checked by `sessionServes`); one stored before the minter was recorded counts as the saved (or dev override) address's, so it never goes to a new address the user types. Tokens refresh before use and again on any 401. Concurrent 401s must not sign the user out, and sign-in must never be left spinning (regressions fixed in 0.1.8 and 0.1.9). If `/api/status` reports `auth_required: false`, sign-in is skipped. Cleartext is local-only by app logic (`auth/server_address.dart`, `isLocalHost`: loopback, RFC 1918, link-local, CGNAT/tailnet, IPv6 ULA, `.local`/`.lan`/`.home.arpa`/`.internal`/`.ts.net`, single-label names): `normalizeServerUrl` gives a schemeless public host `https://`, the setup screen asks (`confirmCleartextServer`) before an `http://` public address and `connect` refuses one without `allowCleartext` (saved addresses are exempt), and a probe redirect to cleartext public is refused. Android keeps `usesCleartextTraffic` because its network security config cannot express private ranges. A failed connect is classified in `auth/connect_failure.dart`; the setup screen adds a VPN hint for tailnet/private addresses, and `network/network_signals.dart` (`connectivity_plus` plus app resume) makes `AuthController` retry the saved server after a network failure. VPN detection is only a hint, never a gate: iOS and macOS cannot report it. An untrusted certificate (Caddy's `tls internal`) is its own failure kind with a hint on trusting the root; on Android, where Dart reads only the system store, `network/user_certificates.dart` adds the user-installed CA certificates to the default `SecurityContext` at launch, in `prepareBackgroundIsolate` and on resume. `--dart-define=HERMES_SERVER_URL=<url>` overrides the saved server address, for dev and tests.
