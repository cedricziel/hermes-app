# Native pieces (Runner targets, extensions, packages)

**Native pieces.** The iOS Runner declares the background refresh's BGTask identifier `$(PRODUCT_BUNDLE_IDENTIFIER).refresh` (`BGTaskSchedulerPermittedIdentifiers`, `UIBackgroundModes: fetch`; it also declares `audio` and `voip` for voice calls, see `packages/hermes_calls`) and registers its launch handler in `didFinishLaunching` (`WorkmanagerPlugin.registerPeriodicTask(withIdentifier:earliestBeginInSeconds:)`), because BGTaskScheduler refuses a handler added later; it does not run on macOS. `ios/ShareExtension` (share sheet, `receive_sharing_intent`, linked by a version-pinned path in `project.pbxproj`, so a plugin upgrade must be mirrored there) and `ios/HermesLiveActivity` (the app's one WidgetKit extension despite its name, bundle ID `com.cedricziel.hermesApp.LiveActivity`: the Live Activity, the Home Screen widgets Recent chats, Needs you and Board, and the Lock Screen and StandBy ones (Needs you's accessory families, New Chat, Dictate and Quick launch), which draw the surface snapshot only; new widgets join its `HermesLiveActivityBundle`, and renaming the target would orphan its provisioning profile), `ios/HermesSurfaceKit` (the Swift package the system surfaces share: `SurfaceSnapshot`, the lenient reader of the snapshot, and the pure `RecentChatsModel`/`NeedsYouModel`/`NeedsYouAccessoryModel`/`QuickLaunchModel`/`BoardModel` that decide what each widget shows, the App Intents `ChatEntity`/`ProfileEntity` (queries answered from the snapshot: recent chats newest first, a chat the snapshot no longer holds still opens as "Chat"; under App Lock, when every title is empty, no chat is offered; the app's "New chat" label is shown with profile and age and never matched; the Open Chat control's label is fixed) with `OpenChatIntent`, `NewChatIntent`, `DictateIntent` and the Open Chat control's `OpenChatControlIntent` (each returns an `OpenURLIntent` on a `DeepLink`; compiled into the Runner and the extension, whose bundle also holds the New Chat, Dictate and Open Chat controls in `IntentControls.swift`; the one `AppShortcutsProvider`, `HermesAppShortcuts`, and the `hermes_app/intents` channel that `lib/src/intents/intent_shortcuts.dart` calls after each snapshot write are Runner-only, in `ios/Runner/HermesAppShortcuts.swift`), and `DeepLink`, the only Swift builder of `hermes://` links, whose output `test/deep_links/deep_link_fixture_test.dart` pins in `Tests/Fixtures/deep_links.json` (`UPDATE_DEEP_LINK_FIXTURE=1` rewrites it); the extension compiles its sources directly, in the same module, so its tests run with `swift test` in CI's "Test watch core" job; `test/fixtures/surface_snapshot_v1.json` is the Dart-written fixture its tests decode, kept equal to the copy in `ios/HermesSurfaceKit/Tests/Fixtures/`), `ios/HermesWatch` (the watchOS companion app embedded in the iOS app; it has no network of its own and asks the phone, which answers in `lib/src/watch/`. It keeps the chat list and the listed chats in its Caches directory, hands the requests that never reached the phone over with the next one, which the phone logs as `watch.delivery.failed`, and offers fixed quick-reply chips (Continue, Yes, No, Summarize) and double tap (starts or stops and sends a voice message) in a chat. A send that waits on an approval or a question answers `waiting` at once and the watch asks again with the same send id while the user answers from the mirrored notification; see the `watch-simulator` skill). macOS has its own share inbox (`share/macos_share_inbox.dart`), which also carries the Services menu's "Ask Hermes" (`NSServices` in `macos/Runner/Info.plist`, `AskHermesService.swift`): the provider queues the selection in memory (never on disk, at most 20,000 characters), `AppDelegate` merges it into the `take` answer, and the inbox turns it into a `SharedQuote`, which `ChatScreen` puts, block-quoted and unsent, in the composer of a new chat (`ShareController` holds only the latest and drops it on sign-out). On macOS, Debug builds use bundle ID `com.cedricziel.hermesApp.dev` (`macos/Runner/Configs/AppInfo.xcconfig`), so every macOS extension's Debug ID must be prefixed with it; iOS uses `com.cedricziel.hermesApp` in every configuration. Release and TestFlight builds go through `fastlane` (lanes in `fastlane/Fastfile`, store metadata in `fastlane/metadata/`). On Android, Auto Backup stays on but `AndroidManifest.xml` points `android:fullBackupContent` (Android 11 and older, `res/xml/backup_rules.xml`) and `android:dataExtractionRules` (12 and newer, `res/xml/data_extraction_rules.xml`, cloud backup and device transfer) at rules that exclude the `home_widget` plugin's `HomeWidgetPreferences.xml` and `InternalHomeWidgetPreferences.xml` from the `sharedpref` domain: the surface snapshot holds chat titles and snippets and must not reach a backup or a new phone, which writes its own. Anything else the app stores is unchanged (the `shared_preferences` file is still backed up). `flutter_secure_storage`'s Keystore-bound values cannot be decrypted on another device after a restore: stores with the default `resetOnError` reset and read as empty, but the chat queue's keys (`lib/src/chat/queue_storage/queue_keys.dart`, `resetOnError: false`) would throw, since the plugin only logs then. That is not a regression of this change, and whether the plugin's preferences should also be excluded is an open question.

**Native code assets (flutter_soloud).** `flutter_soloud` 5.3.0 (pinned exactly in `pubspec.yaml`) builds its engine in a Dart build hook (`hook/build.dart`, native assets, no per-platform CMake or pod script of ours) on every platform the app builds for, iOS included, though only Android, macOS, Windows and Linux ever initialise it (`PortableCallBridge`); on iOS CallKit's graph plays, and the plugin class that observes engine lifecycle is registered but does no work. By default the hook downloads prebuilt Opus, Ogg, Vorbis and FLAC archives from a GitHub release on every build. PCM needs none of them, so the root `pubspec.yaml` sets the hook user-define `hooks: user_defines: flutter_soloud: no_xiph_libs: true`: the build skips the download and links nothing but the platform's C and C++ runtime (the Linux library depends on libstdc++, libgcc, libc and libm; `dl` is part of libc; miniaudio loads PulseAudio or ALSA at run time, which `pulseaudio-utils` in the `.deb` already provides, so `scripts/package-linux.sh` needs no change). The same block sets `enable_vst3: false`: the hook would otherwise let the environment variable `SOLOUD_ENABLE_VST3` switch on a download of prebuilt VST3 hosting libraries from the repository's `latest` release without a checksum. No workflow or script sets that variable (checked with a search of `.github` and `scripts`), and a user-define wins over it. Verified on Linux x86_64: `flutter build linux --release` logs "Xiph libs [disabled]" and fetches nothing from `releases/download`. The hook compiles C++ with the platform toolchain (clang on Linux, the NDK on Android, Xcode, MSVC), which the workflows already have for Flutter itself; the Linux job needs no extra package. The plugin is not registered in the macOS conversation-window and quick-panel engines (they register a fixed plugin list, `record` only in the panel). Android declares `MODIFY_AUDIO_SETTINGS` for the call's audio mode and speaker switch. `media_kit`, already a dependency, has no push-PCM API (files, URLs and memory buffers only), so it would have needed a local HTTP source; `flutter_soloud` was chosen over it.

**Secure window (Android).** `MainActivity.kt` serves the channel `hermes_app/secure_window` with one method, `setSecure(bool)`, which only calls `window.addFlags(FLAG_SECURE)` or `clearFlags(FLAG_SECURE)` and holds no state. The counting is Dart's: `SecureWindow` (`lib/src/server_care/secure_window.dart`) keeps the number of pages that asked, sends `true` when the first one does and `false` when the last lets go, and does nothing off Android (iOS has no such flag; there `PrivateSurface` blanks the page while the app is inactive). The Logs page holds it while it is on screen; a page that fails to start releases it. No plugin was used (`screen_protector` and `no_screenshot` were weighed; see `openspec/changes/server-care/design.md`, open question 1).

**flutter_soloud: why, the pin, what its build does, licences.** The call needs a player that takes PCM as it is generated (a reply starts before it is complete), on Android, macOS, Windows and Linux, with the Android output tagged as voice communication so the platform's echo canceller sees it as the far end. Considered and left out (pub.dev, 2026-11-15): `media_kit` (already a dependency; files, URLs and memory buffers only, no push-PCM), `just_audio` (no Windows or Linux; sources, not pushed PCM), `audioplayers` (whole sources: files, URLs, byte buffers), `flutter_pcm_sound` (Android, iOS and macOS only), `sound_stream` (Android and iOS only), `mp_audio_stream` (all platforms and MIT, push PCM, but 16 likes and about 4,700 downloads in 30 days against 618 and 192,000 for `flutter_soloud`, and an init, push and uninit API with no setting for the Android output usage), `flutter_sound` (all platforms, MPL-2.0; a whole recorder and player suite that overlaps `record` and `audio_session`, for one function). `flutter_soloud` is MIT, has all five platform tags, and `AndroidAAudioAttributes.voiceCommunication` in `init`. It is pinned exactly (`flutter_soloud: 5.3.0`, no caret) because its build hook is native code that runs on every build: a bump is a reviewed change, not a `pub upgrade`. What `hook/build.dart` 5.3.0 does, by platform: it always compiles the package's own `src/` (SoLoud, miniaudio, the filters, pffft) with `native_toolchain_c`: clang and clang++ on Linux, clang from Xcode on macOS and iOS (miniaudio's backend as Objective-C++), the NDK's clang on Android (static libc++, NEON), MSVC on Windows. Downloads: with no user-define it fetches `xiph-macos.tar.gz`, `xiph-ios.tar.gz`, `xiph-android.tar.gz`, `xiph-windows-<arch>.zip` or `xiph-linux-<arch>.tar.gz` (Opus, Ogg, Vorbis, FLAC) plus their headers from `github.com/alnitak/flutter_soloud_prebuilds` releases (`latest`), and, only on desktop and only when `enable_vst3` or `SOLOUD_ENABLE_VST3` is true, a `vst3-*` archive. This repo sets the two user-defines, `no_xiph_libs: true` and `enable_vst3: false`, so no platform downloads anything and everything is compiled from the pub package. The line to look for in a CI log is `[flutter_soloud] Building on <platform> (<arch>) with Xiph libs [disabled]` with no `VST3` after it; none of `Downloading prebuild archive`, `Extracting archive` or `releases/download` may appear after it. Licences: the package is MIT (`LICENSE`, 2024, the flutter_soloud Authors). It bundles SoLoud (zlib/libpng, Jari Komppa; its own file says no attribution in binary form is needed), miniaudio 0.11.x (public domain or MIT-0, no notice needed), signalsmith-stretch and signalsmith-linear (MIT, notice required), pffft (FFTPACK terms, notice required in the documentation of a binary distribution) and small public-domain or Unlicense parts of SoLoud's audio sources (`speech`, `ay`, `tedsid`). Flutter's licence collection reads one LICENSE file at the top of each pub package, so it gets the MIT text and not the bundled ones, and the app had no licence page at all. So `lib/src/settings/third_party_notices.dart` registers the SoLoud, signalsmith and pffft texts with `LicenseRegistry` (called from `main`; lazy, it touches no audio code), and the About dialog has an Open source licenses row that opens Flutter's licence page, which lists them with every other package's. A bump of `flutter_soloud` must recheck that file against the package's `src/**/LICENSE*`. App size cost is to be read from the PR's CI artifacts (the `.so` per ABI, the `.app` and the Windows folder), not estimated here. **The guard.** Three things check the claims above on every change, so they are not a one-off manual reading. (1) `test/dependency_flutter_soloud_guard_test.dart` (in every test shard run) parses `pubspec.yaml` with `package:yaml` and fails when `hooks.user_defines.flutter_soloud` loses `no_xiph_libs: true` or `enable_vst3: false`, when the pin stops being an exact version, when it differs from `kFlutterSoloudNoticesVersion` in `lib/src/settings/third_party_notices.dart` or from the version `pubspec.lock` resolves, or when the registered notices stop naming SoLoud, signalsmith-stretch, signalsmith-linear and pffft; that nothing but `portable_call_audio.dart` imports the package is checked by `test/voice/calls/portable_call_lifecycle_test.dart`. (2) The `Build Linux (release)` job builds with `flutter build linux --release -v`, keeps the output in `build/flutter_build_linux.log` and runs `scripts/check-soloud-build-log.sh`, which needs `[flutter_soloud] Building on Linux (<arch>) with Xiph libs [disabled]` with nothing after it (no `, VST3 [prebuilt]`) and none of `Downloading prebuild archive`, `Extracting archive`, `releases/download`, `Configuring ogg|opus|vorbis|flac` or `Cloning`; the job then checks that `libflutter_soloud_plugin.so` is in the bundle. Flutter does not copy the hook's own output into the verbose log: the line is in `.dart_tool/hooks_runner/flutter_soloud/<hash>/stdout.txt`, so the script reads the log and those files (the hook only runs when its inputs changed, which a fresh CI checkout always does; a local rerun needs `.dart_tool/flutter_build` cleared). (3) `scripts/test_check_soloud_build_log.py` (run by the `Test scripts` step) feeds the script a good log, a missing line, VST3 and each forbidden string. Only Linux is checked in CI; the other platforms run the same hook with the same user-defines, but nothing reads their output. **When the guard fails:** a failing pubspec test means a user-define was removed, so put it back (or, if the hook changed, read `hook/build.dart` of that version and update the guard with it). After a deliberate bump of `flutter_soloud`, read the new `hook/build.dart` for downloads and print lines, recheck the bundled licences under `src/**/LICENSE*`, update `third_party_notices.dart` and bump `kFlutterSoloudNoticesVersion` in the same commit; if the hook's print line changed, change the regular expression in `scripts/check-soloud-build-log.sh` and its test.
