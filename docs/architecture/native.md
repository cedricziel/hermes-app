# Native pieces (Runner targets, extensions, packages)

**Native pieces.** The iOS Runner declares the background refresh's BGTask identifier `$(PRODUCT_BUNDLE_IDENTIFIER).refresh` (`BGTaskSchedulerPermittedIdentifiers`, `UIBackgroundModes: fetch`) and registers its launch handler in `didFinishLaunching` (`WorkmanagerPlugin.registerPeriodicTask(withIdentifier:earliestBeginInSeconds:)`), because BGTaskScheduler refuses a handler added later; it does not run on macOS. `ios/ShareExtension` (share sheet, `receive_sharing_intent`, linked by a version-pinned path in `project.pbxproj`, so a plugin upgrade must be mirrored there) and `ios/HermesLiveActivity` (the app's one WidgetKit extension despite its name, bundle ID `com.cedricziel.hermesApp.LiveActivity`: the Live Activity, the Home Screen widgets Recent chats, Needs you and Board, and the Lock Screen and StandBy ones (Needs you's accessory families, New Chat, Dictate and Quick launch), which draw the surface snapshot only; new widgets join its `HermesLiveActivityBundle`, and renaming the target would orphan its provisioning profile), `ios/HermesSurfaceKit` (the Swift package the system surfaces share: `SurfaceSnapshot`, the lenient reader of the snapshot, and the pure `RecentChatsModel`/`NeedsYouModel`/`NeedsYouAccessoryModel`/`QuickLaunchModel`/`BoardModel` that decide what each widget shows, the App Intents `ChatEntity`/`ProfileEntity` (queries answered from the snapshot: recent chats newest first, a chat the snapshot no longer holds still opens as "Chat"; under App Lock, when every title is empty, no chat is offered; the app's "New chat" label is shown with profile and age and never matched; the Open Chat control's label is fixed) with `OpenChatIntent`, `NewChatIntent`, `DictateIntent` and the Open Chat control's `OpenChatControlIntent` (each returns an `OpenURLIntent` on a `DeepLink`; compiled into the Runner and the extension, whose bundle also holds the New Chat, Dictate and Open Chat controls in `IntentControls.swift`; the one `AppShortcutsProvider`, `HermesAppShortcuts`, and the `hermes_app/intents` channel that `lib/src/intents/intent_shortcuts.dart` calls after each snapshot write are Runner-only, in `ios/Runner/HermesAppShortcuts.swift`), and `DeepLink`, the only Swift builder of `hermes://` links, whose output `test/deep_links/deep_link_fixture_test.dart` pins in `Tests/Fixtures/deep_links.json` (`UPDATE_DEEP_LINK_FIXTURE=1` rewrites it); the extension compiles its sources directly, in the same module, so its tests run with `swift test` in CI's "Test watch core" job; `test/fixtures/surface_snapshot_v1.json` is the Dart-written fixture its tests decode, kept equal to the copy in `ios/HermesSurfaceKit/Tests/Fixtures/`), `ios/HermesWatch` (the watchOS companion app embedded in the iOS app; it has no network of its own and asks the phone, which answers in `lib/src/watch/`. It keeps the chat list and the listed chats in its Caches directory, hands the requests that never reached the phone over with the next one, which the phone logs as `watch.delivery.failed`, and offers fixed quick-reply chips (Continue, Yes, No, Summarize) and double tap (starts or stops and sends a voice message) in a chat. A send that waits on an approval or a question answers `waiting` at once and the watch asks again with the same send id while the user answers from the mirrored notification; see the `watch-simulator` skill). macOS has its own share inbox (`share/macos_share_inbox.dart`), which also carries the Services menu's "Ask Hermes" (`NSServices` in `macos/Runner/Info.plist`, `AskHermesService.swift`): the provider queues the selection in memory (never on disk, at most 20,000 characters), `AppDelegate` merges it into the `take` answer, and the inbox turns it into a `SharedQuote`, which `ChatScreen` puts, block-quoted and unsent, in the composer of a new chat (`ShareController` holds only the latest and drops it on sign-out). On macOS, Debug builds use bundle ID `com.cedricziel.hermesApp.dev` (`macos/Runner/Configs/AppInfo.xcconfig`), so every macOS extension's Debug ID must be prefixed with it; iOS uses `com.cedricziel.hermesApp` in every configuration. Release and TestFlight builds go through `fastlane` (lanes in `fastlane/Fastfile`, store metadata in `fastlane/metadata/`). On Android, Auto Backup stays on but `AndroidManifest.xml` points `android:fullBackupContent` (Android 11 and older, `res/xml/backup_rules.xml`) and `android:dataExtractionRules` (12 and newer, `res/xml/data_extraction_rules.xml`, cloud backup and device transfer) at rules that exclude the `home_widget` plugin's `HomeWidgetPreferences.xml` and `InternalHomeWidgetPreferences.xml` from the `sharedpref` domain: the surface snapshot holds chat titles and snippets and must not reach a backup or a new phone, which writes its own. Anything else the app stores is unchanged (the `shared_preferences` file is still backed up). `flutter_secure_storage`'s Keystore-bound values cannot be decrypted on another device after a restore: stores with the default `resetOnError` reset and read as empty, but the chat queue's keys (`lib/src/chat/queue_storage/queue_keys.dart`, `resetOnError: false`) would throw, since the plugin only logs then. That is not a regression of this change, and whether the plugin's preferences should also be excluded is an open question.

**Secure window (Android).** `MainActivity.kt` serves the channel `hermes_app/secure_window` with one method, `setSecure(bool)`, which only calls `window.addFlags(FLAG_SECURE)` or `clearFlags(FLAG_SECURE)` and holds no state. The counting is Dart's: `SecureWindow` (`lib/src/server_care/secure_window.dart`) keeps the number of pages that asked, sends `true` when the first one does and `false` when the last lets go, and does nothing off Android (iOS has no such flag; there `PrivateSurface` blanks the page while the app is inactive). The Logs page holds it while it is on screen; a page that fails to start releases it. No plugin was used (`screen_protector` and `no_screenshot` were weighed; see `openspec/changes/server-care/design.md`, open question 1).
