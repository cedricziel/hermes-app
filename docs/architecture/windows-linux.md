# Windows and Linux

**What the desktop builds are** (`windows/`, `linux/`, `scripts/package-linux.sh`, `.github/workflows/ci.yml`, `release-please.yml`). Both are stock Flutter runners with no custom native code (no method channels, unlike `macos/Runner`). CI builds Windows (`flutter build windows --release`) and Linux (release bundle, packaged by `scripts/package-linux.sh` into a tar.gz and a `.deb`, x86_64 and arm64) and never launches either. Releases attach an unsigned Windows x64 zip (no MSIX, no installer), so SmartScreen warns and Windows notifications would run without package identity. The `.deb` depends on GTK 3, `libsecret`, `libjsoncpp`, `pulseaudio-utils` and `libmpv2`.

**How a feature is turned off.** There is no shared "desktop" helper. Each feature checks `defaultTargetPlatform` itself and, on a platform it does not list, returns null or a no-op (`createPlatformShareInbox` returns `NoopShareInbox`, `SurfaceSnapshotStore` and `DeepLinks` are `null`, `BackgroundScheduler._supported` is false). Windows and Linux therefore fall through every list that names iOS, Android and macOS. Where a check names `windows`/`linux` it enables the feature (`DesktopNavigationCommands` in `app.dart`, the Bot Screen's desktop key and focus handling, the Ctrl-V attachment paste, which uses Ctrl wherever the platform is not Apple).

Everything below is read from code and plugin metadata. Neither platform was run.

## Gaps

Cheap to close, in the order that helps most:

1. **Notifications on Windows and Linux.** `flutter_local_notifications` (^23.0.2, already a dependency, maintained by MaikuB) already ships `flutter_local_notifications_windows` (FFI, WinRT toasts) and `flutter_local_notifications_linux` (D-Bus, Desktop Notifications spec). The Windows FFI plugin is already in `windows/flutter/generated_plugins.cmake`; the Linux one is pure Dart and needs no native step. The work is in `local_notification_service.dart`: add `LinuxInitializationSettings` (needs a default action name) and `WindowsInitializationSettings` (app name, an AppUserModelID and a GUID) to `_start`, extend `_supported`, build `LinuxNotificationDetails` and `WindowsNotificationDetails` next to the Android and Darwin ones, and extend the `defaultTargetPlatform` checks in `notification_providers.dart` and `agent_message_watcher.dart` so request answers and messages from Hermes follow. Limits to state in the UI or docs: the Linux plugin's actions depend on the notification server's capabilities (`getCapabilities`); the Reply action (`textInput` in `request_notifications.dart`) cannot work on Linux because `flutter_local_notifications_linux` has no text input, so only the button actions apply; on Windows an unpackaged app cannot cancel or list shown toasts (that needs MSIX, e.g. the `msix` package) and `periodicallyShow` throws, which the app does not use. Nothing here needs a new dependency.
2. **App Lock explanation.** `app_lock_dialog.dart` always tells the user to set up Face ID, Touch ID or a passcode in system settings, which on Linux can never help. Say instead that App Lock is not available on Linux (no system prompt exists for it), and on Windows point to Windows Hello. This is a text change plus a platform branch, with the strings moved to the ARB files. No plugin to add; a Linux lock would need a PAM or polkit prompt, which has no mature Flutter plugin.
3. **Linux keyring message.** When `libsecret` finds no Secret Service, tell the user to install and unlock GNOME Keyring or KWallet instead of a generic sign-in failure. Needs a verified failure path on a Linux desktop first.
4. **`.deb` recommendations.** Add `Recommends: gnome-keyring | kwalletmanager` (a Secret Service for the session) and `xdg-desktop-portal` (file picker and Save as). One-line packaging changes. Dictation needs no extra package.
5. **`hermes://` links.** `app_links` already supports Linux and Windows. It needs the scheme registered (`MimeType=x-scheme-handler/hermes;` and `%u` in the `.desktop` `Exec`; a registry entry from an installer on Windows) and single-instance handling (`linux/runner/my_application.cc` uses `G_APPLICATION_NON_UNIQUE`), then the platform lists in `deep_link_providers.dart` extended. Medium: needs an installer on Windows.

Larger and not planned here: background refresh (`workmanager` has no desktop support; a tray resident process would be a different design), drag out, quick panel, share targets, signing and an installer for Windows.
