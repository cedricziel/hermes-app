# Telemetry

**Telemetry** (`lib/src/telemetry/`). OpenTelemetry to SignalDB through the `flutter_otel` package and its `dart_otel_*` siblings from pub.dev (source: `cedricziel/flutter-otel`, ours — file upstream PRs there rather than working around gaps locally). It is off unless `OTEL_EXPORTER_OTLP_ENDPOINT` is passed via `--dart-define`. When off, no SDK exists and no `traceparent` header is added. Telemetry code must never break the app (see `safely.dart`). Spans, request logs and `AuthController` events describe the Hermes server they belong to with `hermes.*` attributes (version, install ID, auth, gateway mode, profile count, health) read from its `/api/status` answer (`telemetry/hermes_server_attributes.dart`): `Telemetry.forConnection` builds an interceptor and event logger per connection, `AuthController` swaps them when a probe succeeds and drops them when a connect starts or on Change Server, so a request keeps the server it was sent to. They are never resource attributes, since one app can talk to several servers. A burst of requests failing with the same connection-level `error.type` (`connectionError`, a timeout, `unknown`; never `badResponse`) logs its first record and, 10 s later, one summary with `log.repeat_count` (`telemetry/burst_deduping_logger.dart`); every request keeps its span. `SuspensionMarkingTracer` (`telemetry/suspension_marking_tracer.dart`) marks an HTTP or gateway span that spans a pause of the app, or the return from one, with `app.suspended: true`, since Dart timers stop while the app is suspended and such a span measures the time away. The minute polls (`ScheduleWatcher`, `AgentMessageWatcher`, `SchedulesController`) and the chat's 5 s running-chats poll skip ticks after failures (`network/poll_backoff.dart`: `2^n - 1` ticks after `n` failures, capped); a return to the front or a restarted poll starts without the wait (the watchers also look at once). Breadcrumbs don't get them, except `server.connected` with the version. The connection's telemetry travels with `HermesRepositories` (`telemetry`, captured in `forAuth`): screens build a new gateway or Kanban tracer for each socket from it (`telemetry.gateway()`, `.kanban()`; a tracer links messages to the last upgrade it traced, so two sockets never share one), and the gateway transport, Kanban board, plugin and skills screens log through its `events`. The watch bridge and `TokenStore` keep the root logger. The gateway transport logs `gateway.reconnect`, `gateway.turn_settled`, `gateway.event_unmapped` (a frame type the app shows nothing for, once per type per connection) and `gateway.send_failed` (the step a send stopped at and the kind of error) through the `AppEventLogger`, never with message text. Uncaught Flutter and async errors are logged with full message, stack trace and recent breadcrumbs via `flutter_otel`'s `installCrashReporting`/`BreadcrumbTrail`, wired up in `Telemetry.logUncaughtErrors`/`Telemetry.events`: unlike the package's privacy-preserving `installUncaughtErrorLogging` (type only, for an arbitrary OTLP endpoint), the crash reporter keeps full detail because the endpoint here is always the operator's own self-hosted SignalDB. A recurring error is logged once and then summarized with a repeat count, and message and stack are trimmed to fit SignalDB's attribute size limit (details in `openspec/specs/telemetry/spec.md`). The crash record's breadcrumbs also say what the user was doing: `Breadcrumbs` (`telemetry/breadcrumbs.dart`, provided next to `AppEventLogger`; `Breadcrumbs.none` when telemetry is off or no provider is above) adds a crumb to the same trail without exporting a log record. `AppShell` records `nav.destination` and `app.lifecycle` (resumed, paused), `ChatController` records `chat.threads.loaded` (`switched`, `count`), `chat.thread.selected|new|closed`, `chat.open.requested|failed` and `chat.reply.started|ended` (`outcome`), and `ConversationWindows` records `window.opened|closed|key`; the gateway's `gateway.*` events are crumbs already, so they are not repeated. Crumbs hold fixed names, counts, flags and outcomes only: never text, titles, profile names, server addresses or ids. The trail keeps the last 40.

**Files** (`lib/src/files/files_telemetry.dart`). `FilesTelemetry` (one per connection) records the spans `files.list`, `files.download` and `files.preview` (`kind`, optional `size` bucket, `outcome`), the log events `files.unsupported` (once), `files.list_failed` and `files.download_failed` (`kind`), and the crumbs `files.opened` (`source`), `files.preview.opened` (`kind`), `files.saved` (`action`), `files.secret.warned` and `files.hidden.toggled` (`on`). Every value is a fixed name, bucket or flag: never a path, file or folder name, profile, `cwd`, server address or content. `FilesController` is the only caller of the crumbs and the preview span. The controller's 10 s `answerTimeout` is the total time a listing, `git-root`, `default-cwd` or `read-text` request may take before it ends as `unreachable` and is never resent; a download is not bounded by it but by the repository's 30 s idle timeout (no chunk for that long) and by Cancel.
