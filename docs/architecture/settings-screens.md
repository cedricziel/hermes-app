# Settings screens: plugins, MCP servers, helper models, model providers

**Settings pages** (`lib/src/widgets/settings_scaffold.dart`, `grouped_list.dart`, `settings_search_field.dart`). Skills, Messaging, Plugins, MCP servers and Helper models share one chrome. `SettingsScaffold` takes a title, a subtitle (profile · count), `SettingsBarAction`s (a button, or `.menu` with `AdaptiveMenuItem`s that act through `onTap`), optional tabs and a `SettingsSearch`, and draws the platform's bar: iOS a 44 pt bar with the title centered, macOS the `MacToolbar` with back, tabs (`MacToolbarTabs`), search and actions in it, Material a 56 pt bar with pill tabs (`PillSegmentedControl`, which `AdaptiveTabBar` now draws on Material). There is no floating button; adding is a bar action. Lists are `GroupedListView` of `GroupedSection`s (header, footer, inset separators) holding `GroupedRow`s (title, inline meta, a subtitle of one line unless `subtitleMaxLines` allows more, warning and error lines that wrap, a muted value of at most half the row and chevron, or a trailing widget; above the default text size a value that does not fit beside the title stacks under it, and only a row with `wrapWhenStacked` lets its title and subtitle wrap in full there, otherwise they keep `titleMaxLines` and `subtitleMaxLines`) and `GroupedSwitchRow`s; `GroupedMetrics.of(context)` has each platform's sizes.

**Shared widgets.** `AppBanner` (`lib/src/widgets/app_banner.dart`, tones `AppBannerTone`: success, warning, error, neutral) is the one tinted note box with an icon, title, optional detail and action. It is a polite live region, and status is told by its icon and the words of its title. In the wave 4 design records "Banner" and "the shared Banner" mean `AppBanner`; the class is not called `Banner` because Material already has one. `DestructiveTintButton` (`destructive_tint_button.dart`) is the destructive action drawn tinted in the error colour with an outline, never filled (44 pt on iOS, 48 dp on Material, 28 pt on a Mac; busy and disabled states), so a screen's one filled button stays the safe one. `LoadingSkeleton` and `CommandRow` (a copyable shell command) live here too; server care builds on them.

**Secret fields** (every screen that takes a key, token or password). Typed secrets are obscured by default and have a Show/Hide control (a 44 pt touch target on iOS and iPadOS, 48 dp on Android, a standard Mac button) labelled "Show key" / "Hide key". Under the field a muted line, announced to screen readers, reads "<N> characters entered"; the count is never stored. A shown value is hidden again when the lifecycle leaves `resumed` (`inactive` included), when a check or save starts, after any failed save, and when the form closes; the shown state is never persisted or restored. Going inactive or to the background only hides a shown value; the typed text stays. The typed text is cleared only when App Lock locks the app, when the form closes, and when the answer to a save is lost (the value may already be saved, so the field is cleared and the message asks to paste it again). After a plain failed save the typed value stays in the field, hidden, so it can be edited. A saved value is never revealed (no `POST /api/env/reveal`). The shared widget is `SecretFieldRow` (`lib/src/widgets/secret_field_row.dart`), built on `GroupedTextFieldRow` with autocorrect, suggestions, keyboard learning, smart dashes and quotes and autofill off, the visible-password keyboard on Android, one line and no `restorationId`; its Widgetbook use cases are hidden, shown, hidden again on going inactive, after a failed save, and after a lost answer (cleared). Model providers (`openspec/changes/provider-setup`) and toolsets use it; a new feature that takes a secret points here instead of restating the rule.

**Plugins** (`lib/src/plugins/`). The chat sidebar's Plugins row opens a screen with three tabs. Installed lists the dashboard's agent plugins (`GET /api/dashboard/plugins/hub`) and enables, disables, updates, removes and hides them; it does not list Kanban or Achievements, which the hub reports apart as dashboard-only extensions. Catalog (`GET /api/dashboard/plugins/catalog`, loaded when first opened) searches the curated catalog and installs from it, and installs from a Git URL behind an unreviewed-code warning; the typed URL can hold a token, so it is never logged or kept. Providers (the `providers` object of the same hub, loaded when first opened) picks the memory provider and context engine: only providers the server reports as ready can be picked, the rest list what they need on the server (the app runs nothing), and Save sends only the fields that changed to `PUT /api/dashboard/plugin-providers`. `PluginsController`, `CatalogController` and `ProvidersController` hold the state. Details are a bottom sheet below 900 px and a pane at 900 px or wider. The screen shows the chat's profile (or the one picked on the Mac Profiles page): `HermesPluginManagerRepository.forProfile` sends `profile` to the hub, visibility and provider routes, but install, enable, disable, update and remove take none, so Hermes runs them for the dashboard's own profile. The generated client puts a plugin's name into the path unencoded, so the repository encodes it. An install can outlast the client's 30 s timeout, so a timeout is reported as "still installing", not as a failure. `PluginsScreen.initialTab` (`PluginsTab`) picks the tab shown first; the Memory screen's provider row opens Providers, and the other tabs stay unrequested.

**MCP servers** (`lib/src/mcp/`). List, switch, test and remove the MCP servers of the active profile, opened from the chat sidebar. `HermesMcpRepository` wraps the generated MCP calls and parses leniently. `McpServersController` holds one visit's state (the profile learned first, the list, the test results), and `McpServersScreen` and `McpServerDetail` render it, side by side from 900 logical pixels. The bar's "+" (Add server) is a menu: "Browse the catalog" opens `McpCatalogScreen` (Hermes' approved catalog, searched and filtered on the device; `McpCatalogController`), where an entry that is not installed opens `McpInstallPanel` (a bottom sheet, or the right-hand pane from 900 logical pixels) and an installed one opens its server. `McpInstallController` sends the install and, for entries Hermes builds on the server, polls `GET /api/actions/{name}/status`. Credentials live only in the panel's text fields and go into the install request. `McpSignInScreen` waits while the user approves an OAuth sign-in in the browser (`McpServersController.startSignIn`, then polling `GET /api/mcp/oauth/flows/{id}`); Hermes keeps the token and the app never sees the code. "Add a custom server" opens `McpAddServerScreen` (remote or command server) and the overflow menu's "Edit as JSON" opens `McpJsonEditorScreen`, which loads the whole map from `GET /api/config` (the servers route is lossy) and saves it with `PUT /api/mcp/servers`. A command server makes the Hermes host run a program, so `McpServersController.addServer` and `replaceServers` take a required `McpReviewer` and send nothing until it confirms; the screens pass `showMcpCommandReview` (bottom sheet, dialog from 900 px). Bearer tokens, environment values and the editor's text stay in screen state and are cleared after the request.

**Helper models** (`lib/src/settings/helper_models_screen.dart`). The chat sidebar's "Helper models" row lists the chat profile's auxiliary task slots (`GET /api/model/auxiliary`) and opens the shared `showModelPicker` for one, with its "Use the profile's default" entry. The pick is saved once, when the picker closes, with `POST /api/model/set` (`scope: auxiliary`; the default entry sends `provider: auto`, empty model, which Hermes runs on the main model). Hermes may answer `confirm_required` for an expensive model; the screen asks and resends with `confirm_expensive_model`. Changes apply to new sessions only. Below the slots, a "Mixture of agents" section lists the default preset's advisors and aggregator (`GET /api/model/moa`, `MoaSetup`); a change sends the whole config back with `PUT /api/model/moa`, only that slot edited, and keeps the MoA rows closed until it answers. The section is left out when MoA cannot be read.

**Model providers** (`lib/src/providers/`; roadmap 4.1, `openspec/changes/provider-setup`). One screen per profile: `ProvidersScreen` (`providers_screen.dart`) over `ProviderSetupController`, which holds the state and every write; the screen words it, owns the dialogs and sheets and never builds a widget inline (the plain-model widgets are in `widgets/`, built from the controllers' state by `provider_view_mapper.dart`). `HermesRepositories.providers` builds the `ProvidersRepository`.
- Routes and profile scope. Opened from the chat's sidebar and compact drawer ("Model providers", before "Helper models", only while the chat's model options did not answer 404) for the chat's profile, and from the Mac Profiles page (`ProfileSection.providers`, "N connected") for the selected profile. Every request carries that profile (none on a server without profiles). The chat reads its model options again (`ChatController.refreshModelOptions`) whenever the controller's `changes` moves and when the screen closes. Entry points record `providers.opened` with `source` (`sidebar`, `drawer`, `profiles`), starting a connect `providers.connect.started` with `method`, a confirmed removal `providers.remove.confirmed` with `kind`: fixed words only, never a provider, address, model or profile.
- Layout. List beside detail from 900 pt (`isWideLayout`, so a full-screen iPad too; a Mac from `kMacSplitBreakpoint`), else a pushed `ProviderDetailPage`. Forms go through `showProviderSheet` (`provider_flow.dart`): a page sheet on iOS phones, a full-screen dialog on Android phones, a dialog on macOS and wide windows, never a bottom sheet on macOS (`showAdaptiveSheet` is used for all but the Android phone). Escape closes a form and Return does its primary action on desktop. Pull to refresh only on iOS and Android; a Mac has Command R.
- Secrets. Every key field follows the secret field rule above. The sheets own the `TextEditingController`s (`ProviderKeySheet`, `ProviderEndpointSheet`), clear them when App Lock locks (`SecretFieldsLock`), when the form saves and when it closes, and never persist or restore them. A saved key is never revealed (no `POST /api/env/reveal`): a row shows only its last four characters. Signing out or changing the server closes the screen and everything over it; the controller then stops following sign-ins without cancelling them.
- Links Hermes sends (key page, sign-in page) are opened only after `openableLink` (absolute `https`, or `http` to a local host); otherwise the button is not drawn. Endpoint ids and session ids are percent-encoded by the repository.
- Shared widgets changed with the forms: `GroupedTextFieldRow` stacks its label above the field at large text on Apple platforms and takes a `focusNode`; `CommandRow.copyBelowAtLargeText` puts Copy under the command at large text.
