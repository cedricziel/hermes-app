# System surfaces: snapshot, widgets, quick actions, intents, Spotlight

**Surface snapshot** (`lib/src/surfaces/`). One JSON string under `hermes.surface.v1` in the App Group's `UserDefaults` (the `home_widget` plugin; Android keeps it in the plugin's preferences) is what widgets, quick actions, Spotlight and App Intents read, since an extension holds no token and opens no connection. It holds the signed-in flag, current profile, the server's profile names, up to 10 recent chats across profiles (title, a snippet of at most 120 characters, a `hermes://` link), open requests (chat title and kind only, never the command, question or secret), Kanban blocked and in-review counts, and the next schedule run and last failed job; Kanban and schedules are null when the server lacks them. No token, server address or identity, ever. `SurfaceSnapshots` (provided in `main.dart` on iOS and Android) writes it while the app is in front: `ChatController.onSurfaceChange` reports the chat list loading, a reply ending and a request opening or closing with `ChatHints` (the open profile's chats, no extra request), debounced 2 s; other profiles' chats, Kanban and schedules are read at most every 5 minutes and on every move to the background (`SurfaceSnapshotBuilder`: a source that fails or takes over 5 s keeps its previous section). While App Lock is on, titles, snippets and job names are written empty (counts and links stay), and toggling it rewrites at once. Sign-out, an expired session and Change Server write the signed-out form. An unchanged snapshot is still stored again with the newer `updatedAt` (no listener call; widgets reload only when that time is an hour past the one they last reloaded for, since their stale note is due six hours after it), so widgets do not keep saying "Open Hermes to refresh". A reader must treat titles and snippets as `.privacySensitive()` and must never add content the notification body does not already allow. Add a widget's kind to `kSurfaceWidgetKinds` (`widget_kinds.dart`) so a write reloads it; a kind that fails to reload is logged as `widgets.reload_failed` and the others still reload, the store remembers in memory which kinds failed and a refresh inside the hour retries only those (one that always fails costs one reload call per refresh, the others stay on the hourly rule), and the reload time is recorded unless every kind failed. A kind that reads only the signed-in flag (New Chat, Dictate, Quick launch) is also in `kSignedInOnlyWidgetKinds` and reloads only when that flag flips, to save WidgetKit's reload budget. `WidgetUsageReporter` logs `widgets.installed` (kinds, families and counts) at most once a day. A widget with no snapshot, a signed-out one or one older than six hours says "Open Hermes to sign in" or "Open Hermes to refresh", and while App Lock is on rows without a title draw a redacted placeholder, never an invented title.

**Quick actions** (`lib/src/quick_actions/`, iOS and Android, the `quick_actions` plugin). The app icon's long-press menu is New Chat, Dictate and the two newest chats with a title (`quickActionItems`; iOS shows four items at most, so both platforms list the same four). Each item's type is its `hermes://` URL (`deepLinkUri`), and a pick goes through `DeepLinks.open`, the same path as any link. `QuickActionsController` registers the handler before it sets anything, follows `SurfaceSnapshotStore.writes`, and sets items only when the list changed. App Lock and sign-out need no check of their own: the snapshot has empty titles under App Lock (no recents) and `signedIn: false` after sign-out (no items). Android's icons are `res/drawable/quick_*.xml`, kept from resource shrinking in `res/raw/keep.xml`; iOS's are SVG template images in the asset catalog. Log events `quick_action.used` and `quick_actions.update_failed` and the breadcrumb `quick_action.opened` hold the kind, a flag or an error type only.

**Ask Hermes** (iOS App Intent; `lib/src/intents/ask_hermes.dart`, `intents_channel.dart`, `tapped_transport.dart`, `ios/Runner/IntentsBridge.swift`, `HermesSurfaceKit/AskHermes.swift` and `AskHermesIntent.swift`). Siri and Shortcuts send one question and get the reply back without opening the app, also on a locked device (the user's choice; App Lock is the opt-out). `AskHermesIntent` runs `perform()` in the app's process; `AskHermes.answer` owns the 25-second clock and says "Still working — I'll notify you." when it runs out, while the ask goes on; Dart decides 500 ms earlier (`kAskMargin`) so it always speaks first. `IntentsBridge` is the one bridge to Dart for every intent (its header documents the channel `hermes_app/intents`: `ask`, `expire`, `unavailable`, `openLink` from Swift; `ready`, `finished`, `closed` from Dart): the app's engine once that said ready, else a background engine on `intentsMain` (`entry_points.dart`, plugins from `NotificationActions.registerPlugins`) that gets `AskHermes.readyWait` (12 s; a cold start was measured at 5.4 s) and stops 10 s after its last call, kept alive when it was merely slow and reported later as `intent.unavailable` (`ready_timeout`, `engine_start_failed`). It holds a `UIApplication` background task until Dart says `finished` or iOS expires it, and gives up the engine's line at Swift's deadline. New intents add methods to that channel (`IntentsChannel._onCall`) rather than engines. `AskHermes` (Dart) runs `WatchRequestHandler`'s `send` on `withHeadlessHermes(task: 'intent.ask')`, through `TappedTransport` so it sees `ThreadBound`, `PromptFolded` and `ReplyCompleted`; it maps each `HeadlessOutcome` to an `AskOutcome` and Swift words them (the reply is spoken without Markdown, an approval or question never reaches Siri). "Reply ready" and "Reply failed" are posted only after "Still working" was said; request notifications always. Once "Still working" was said the chat is added to `RunningReplies` (`fromAsk`, which the chat screen's pauses keep) so a background run announces the reply if the process is suspended (only once Hermes has the question: a frame, or `PromptAcknowledgement.promptAccepted`, which the gateway transport sets when `prompt.submit` is answered); `clear` on the app's return keeps those entries and `clearAll` on sign-out drops them; the ask forgets the entry when it announced the reply itself, and a turn that ends without a reply (a timeout, a closed socket) posts no "Reply failed" but is left to that check. A question that never reached Hermes after "Still working" posts one "Couldn't send your question" notification whose payload (`q`, at most 4000 characters, none under App Lock) opens a new chat with it unsent (`NotificationTarget.newChat`); a prompt Hermes accepted whose socket then died posts nothing of the kind. A prompt Hermes folded into the chat's running turn answers "Added to the running chat." With App Lock on nothing is sent: the intent calls `continueInForeground` and the bridge hands `hermes://new?prompt=` (`AskHermes.handOverLink`, `DeepLink`) to Dart's `DeepLinks.open` over `openLink`, so a cold launch holds it until the shell is up. The span `background.task` keeps the runtime's `outcome`; the intent's own is `ask.outcome`, with `engine` and `continued` (App Lock and blank asks get a span of their own), and the log event `intent.ask` has `outcome` and `waited_s`. Never log the question, reply, title, profile or ids.

**Request intents** (iOS, `lib/src/intents/request_intents.dart`, `ios/HermesSurfaceKit/.../RequestIntents.swift`, `ios/Runner/RequestIntentsBridge.swift`). "Pending Requests" (no unlock needed) says what waits, from `OpenRequestsStep` read fresh and stored with `refreshSnapshot(pending:)`, falling back to the stored snapshot with "As of <time>," when Dart cannot reach the server; "Answer Approval" (`requiresAuthentication`) reads the approval's command with `ChatTransport.pendingApprovals`, confirms with it, then answers through `RequestAnswerSender` / `answerOpenRequest(..., raisedAsEvent: true)`, the notification buttons' path. Both run in a Flutter engine the Runner's `RequestIntentsBridge` starts on `requestIntentsMain` (channel `hermes_app/request_intents`, calls one at a time, engine kept 10 s) and go through `withHeadlessHermes`; every `HeadlessOutcome` has a sentence ("Sign in to Hermes first.", "Unlock your iPhone first.", "Can't reach your Hermes server."). With App Lock on the list is a count and an answer is refused. The flows live in `HermesSurfaceKit` behind `RequestIntentsBackend`, so `swift test` runs them with a fake.

**Spotlight** (iOS and macOS, `lib/src/spotlight/`, each Runner's `Spotlight.swift`). `SpotlightSettings` defaults to enabled when `hermes.spotlight` has no saved value; saved opt-outs remain off. Settings exposes the switch on both platforms, and the iOS account menu also opens it. `ChatSpotlightIndexer` follows surface snapshots and indexes up to ten recent chats with titles and snippets, skipping unnamed chats. Native calls run serially; subsequent updates change only modified items and remove dropped ones. Switching off, sign-out, server changes and App Lock remove indexed content; failed removals retain a dirty flag for retry. iOS uses a named index with complete file protection and waits for protected data availability. macOS uses a named index and checks `isIndexingAvailable()`, without promising iOS lock-screen protection. Search results arrive through native continuation handlers, remain pending until taken by Dart, and use the existing deep-link flow. On macOS, a result also brings the main window forward. Handoff remains ineligible for search. Existing events report operations, domains and error types without user content.
