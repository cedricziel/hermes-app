# Deep links

**Deep links** (`lib/src/deep_links/`). The app opens `hermes://chat?profile=&id=&prompt=`, `hermes://new?profile=&dictate=1&prompt=`, `hermes://requests`, `hermes://kanban` and `hermes://schedules?profile=&job=` (scheme registered on iOS, macOS and Android; `app_links` delivers the links, with Flutter's own deep-link routing switched off in `Info.plist` and the manifest). `parseDeepLink` and `deepLinkUri` are the only code that reads or writes these URLs: every producer (widgets, quick actions, Spotlight, intents, notifications) must build its link with `deepLinkUri(target)`, never by hand. `DeepLinks` (provided in `main.dart`) keeps the latest link until `AppShell` takes it, so a link opened on the sign-in screen is applied after sign-in and sign-out drops it. `AppShell._openDeepLink` hands chats to the chat through `ChatOpenRequests` (`request(prompt:)`, `requestNew`, `requestOldestPending`); Kanban and Schedules links wait for the first `_detect()` and are ignored by a server without the tab. A `prompt` is added under the composer's draft and never sent; `dictate=1` starts the microphone only if the profile offers it. Breadcrumbs `deeplink.opened` and `deeplink.ignored` hold fixed words only. `hermes-activity://` (Live Activity) and `hermes-share` (macOS share inbox) are separate schemes.
