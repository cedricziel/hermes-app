# Design

## Context

Hermes' bridge (`tools/bot_desktop/rfb_filter.py`) frames KeyEvent (8 bytes), PointerEvent (6), ClientCutText (8 + |n|, rejecting |n| above 256 KiB, the `-MaxCutText` Xvnc is started with) and drops them unless the viewer holds the lease. A negative ClientCutText length is TigerVNC's extended clipboard. `RfbClient` from `bot-screen-rfb-client` sends only non-input messages and keeps its framebuffer size. `bot-screen-live-view` draws the picture with `RawImage` inside an `InteractiveViewer` driven by a `TransformationController`.

## Decisions

- **Client methods.** `pointer(int x, int y, int buttonMask)`, `key(int keysym, {required bool down})` and `cutText(String text)` on `RfbClient`; each throws `StateError` before ServerInit and after the stream ended, checked before the arguments. `pointer` clamps to `0..width-1` and `0..height-1`. Button mask bits: 1 primary, 2 middle, 4 secondary, 8/16 wheel up/down, 32/64 wheel left/right. `scroll(x, y, {dx, dy})` (notch counts, negative for up and left, at most 50 per axis and call) sends one press and one release of the matching wheel bit per notch, vertical first, keeping the buttons the latest `pointer` call held. The four methods are the `RfbInputSink` interface (`rfb/rfb_input_sink.dart`, with `RfbButtons` and `RfbClipboardError`), which `RfbClient` implements.
- **Clipboard encoding.** `cutText` checks every code unit: anything above 0xFF throws `RfbClipboardError.notLatin1` and nothing is sent; more than 256 KiB of bytes (the limit is inclusive, as in `rfb_filter.py`) throws `RfbClipboardError.tooLarge`. Line breaks (`\r\n`, `\r`) are sent as `\n`, and empty text is sent (takeover uses it to clear the remote clipboard). The extended clipboard is not used (see the proposal's non-goals); SetEncodings is unchanged, so Xvnc never sends extended clipboard messages to this client.
- **`KeysymMapper`** (`lib/src/bot_screen/input/keysyms.dart`): a table from `LogicalKeyboardKey` to keysyms for non-printing keys (Escape 0xff1b, Tab 0xff09, Return 0xff0d, BackSpace 0xff08, Insert 0xff63, Delete 0xffff, Home 0xff50, End 0xff57, Page Up 0xff55, Page Down 0xff56, arrows 0xff51–0xff54, F1–F12 0xffbe–0xffc9, Shift L/R 0xffe1/0xffe2, Control L/R 0xffe3/0xffe4, Alt L/R 0xffe9/0xffea, Super L/R 0xffeb/0xffec, Caps Lock 0xffe5). Characters: 0x20–0x7e and 0xa0–0xff as their code point; Backspace, Tab, Line Feed and Carriage Return (both Return), Escape and DEL as the keys they stand for (`0x01000000 + 0x0a` is no key Xvnc can type); every other code point as `0x01000000 + codepoint`; a lone surrogate, and a control character without a key of its own (NUL, the other C0 and the C1 controls), throw `ArgumentError` rather than being replaced or mapped to a Unicode keysym that names no key; Ctrl+letter comes from the logical key with Control pressed. Errors for a bad value (`ArgumentError`) never carry the value. Option `commandAsControl` maps Meta L/R to Control L/R (used by takeover on macOS). The API is `forLogicalKey(LogicalKeyboardKey)` (the table, null for any other key), `forCodePoint(int)` and `text(String)`, which yields a press and a release per code point (grapheme clusters split into code points, CRLF as one Return). Mapping a `KeyEvent` is the caller's job: it takes the table first and the event's character second, and remembers the keysym it pressed to release the same one.
- **Coordinate math** (`screen_geometry.dart`): `ScreenGeometry(framebuffer, pictureRect, transform)`, or `ScreenGeometry.fitted(framebuffer:, viewport:, transform:)` for a picture drawn with `BoxFit.contain` (the way a `RawImage` fills the viewer's child), maps a local position through the inverse of the `InteractiveViewer` transform into picture space, then scales to framebuffer pixels and clamps; positions outside the picture clamp to its edge. Trackpad mode keeps a virtual pointer in framebuffer pixels and moves it by `delta * framebufferWidth / (pictureWidth * scale)` (likewise for height), clamped to the screen. A mouse wheel click (an event of 30 logical pixels or more) is at least one notch, one per 120 pixels; smaller deltas from a smooth wheel gather at 120 pixels per notch; scroll distance from a trackpad accumulates (`ScrollAccumulator`), one notch per 40 logical pixels. A trackpad's two-finger scroll arrives as pan/zoom events, whose pan delta is inverted (fingers up scroll down); a gesture whose scale moves more than 0.05 from 1 is a pinch and stays one, and scrolls nothing. Empty sizes (no screen, no room to draw it) map to the origin instead of dividing by zero.
- **`ScreenGestureLayer`** (`screen_gesture_layer.dart`) sits over the picture, reads the viewer's `TransformationController` at each event, and calls an `RfbInputSink`, so tests record calls. It reads raw pointer events in a translucent `Listener` for what it sends, and joins the gesture arena through one hidden recognizer only to win single-pointer gestures against the `InteractiveViewer`'s pan, which would otherwise move the picture under a drag (a drag at 2x zoom sent almost constant coordinates). The recognizer accepts a mouse button at once, a finger when it moves past the touch slop (ahead of the viewer's pan slop), and a trackpad pan/zoom gesture when it pans with its scale within 0.05 of 1; it rejects when a second finger lands before that, and on a scale change. Two-pointer gestures therefore stay with the viewer, and the layer sends nothing for them (a second finger landing releases a held button and the layer stays silent until every finger is up). A finger that already crossed the slop owns its gesture, so a pinch that starts after a one-finger drag does not zoom. `mode: touch` — tap is move, press and release of button 1; long press (500 ms without moving past the touch slop) is button 3; one-finger pan moves with button 1 held, starting at the point touched. `mode: trackpad` — one-finger pan moves the virtual pointer, tap clicks at it, long press clicks button 3 there (added: there is no other secondary click in this mode), the first move after the slop counts the travel up to it, a mouse also sets the virtual pointer, scrolling happens at the virtual pointer, and a `ValueNotifier<Offset>` (`virtualPointer`, the layer makes its own, starting at the centre, when none is given) holds the pointer's position for a cursor overlay; it is kept on the screen, also when the screen shrinks. Trackpad mode has no way to drag with a button held; `bot-screen-takeover` adds one (tap-and-drag). Mouse input: hover moves, buttons map to the mask (Flutter's primary, secondary and middle to RFB's 1, 4 and 2), `PointerScrollEvent` to wheel notches. The wheel is registered with the pointer-signal resolver so a scrollable around the layer does not scroll too; an `InteractiveViewer` under it reads the wheel itself and zooms regardless, so takeover decides the viewer's `scaleEnabled` while in control. The layer remembers the latest pointer message and skips an identical one, and releases the button it left held when it is disabled, disposed or given another sink or mode, on a cancelled mouse press too. Events of a gesture that began before the layer was disabled or removed are dropped. A closed sink (`StateError`) drops input and the release of a held button. `enabled: false` (the default) builds no listener, sends nothing, and releases a button a drag still held when it turns false.

Platforms: iOS, Android, macOS, Windows, Linux. No native change.

Invariants touched: none recorded. Telemetry is untouched in this change; the typed errors carry no text.

## Risks / Trade-offs

- [Keyboard layouts: keysyms from characters assume Xvnc can produce them] → Xvnc maps keysyms to keycodes itself and assigns spare keycodes to Unicode keysyms.
- [No non-Latin-1 paste] → Refused clearly rather than corrupted; typing such characters on the keyboard still works through Unicode keysyms.
