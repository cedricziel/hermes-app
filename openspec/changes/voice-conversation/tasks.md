Flag lifecycle of `captureStopped` and `capturePaused` (Swift, read, not run):

| Scenario | stopCapture | Flag after | Next call |
| --- | --- | --- | --- |
| Normal End: Dart stopCapture(id), then `end` | callID live and id matches: sets it; `end` sets it again if still live | `end` -> CallKit end -> `finish` -> `endCall()` clears it | `start` calls `endCall()`; tap installed |
| System CallKit end first | `finish` ran `endCall()`, callID nil; Dart's stopCapture is a no-op | never set again | tap installed |
| Native error calling `finish` before Dart teardown | same as above | never set again | tap installed |
| End during a pending start or permission prompt (callID nil) | no-op | not set; the `start` generation bump cancels the start | tap installed |
| End after the permission, callID set, `didActivate` before CallKit performs the end | `end` handler latches it | `finish` clears it; the tap is not installed meanwhile | tap installed |
| Late `stopCapture` after `bridge.end` (`_closeLate`), or of an old call while a new one is live | callID nil: no-op; id of another call: ignored | not set | tap installed |
| Route change inside a live call after stopCapture | already set | `stop()` keeps it, so `start()` installs no tap | n/a |
| Pause sent before `start` ran (attention during prepare) | `start` calls `endCall()`, clearing `capturePaused` | Dart re-sends `pauseCapture` on `activated` | n/a |
| Pause before a failed start | n/a | `finish` -> `endCall()` clears `capturePaused` | not paused |

A late stopCapture from an old call that arrives after a new call is live would stop the new call's capture; the Dart bridge awaits the old call's end first, so it needs a start inside that window (not handled); the portable bridge comes with 6.2.
